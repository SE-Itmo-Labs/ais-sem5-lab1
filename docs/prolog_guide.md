# Prolog: базовый справочник

Краткий конспект по основам языка Prolog: синтаксис, правила, логические
операторы, унификация и бэктрекинг. Примеры взяты из базы знаний `ai.pl`
(тема: Civilization VI).

---

## 1. Базовый синтаксис

### 1.1. Факты

**Факт** — утверждение, которое интерпретатор считает всегда истинным.

```
unit_type(warrior).            // факт с 1 аргументом
civilization(rome, all_roads_lead_to_rome).   // факт с 2 аргументами
```

- Факт заканчивается точкой `.`.
- Имена предикатов и атомы пишутся со **строчной** буквы: `warrior`, `iron`.
- Комментарии: `%` — однострочный.

### 1.2. Предикаты и атомы

**Предикат** — это имя отношения (имя + количество аргументов). Запись
`unit_era/2` означает предикат `unit_era` с 2 аргументами.

**Атом** — константа, начинающаяся со строчной буквы или взятая в кавычки:
`ancient`, `'Москва'`.

### 1.3. Переменные

**Переменная** — начинается с **заглавной** буквы или `_`:

```
?- unit_era(Unit, medieval).
% Unit = crossbowman ; Unit = knight ; Unit = trebuchet.
```

`_` — анонимная переменная (значение неважно):

```
?- unit_resource(X, _).        % любой ресурс
```

### 1.4. Запросы

Запрос начинается с `?-` и завершается точкой:

```
?- unit_type(warrior).
% true.
```

### 1.5. Списки

`[a, b, c]`; разделение головы и хвоста — `[H | T]`:

```
?- [warrior, archer, knight] = [H | T].
% H = warrior, T = [archer, knight].
```

## 2. Правила

**Правило** — логическое выражение «голова :- тело», означающее:
*«голова истинна, если истинны все условия в теле»* (`:-` читается как «если»).

```
unit_available(Unit, Era) :-
    unit_era(Unit, UnitEra),       % условие 1 (и)
    \+ era_before(Era, UnitEra).   % условие 2 (НЕ)
```

```prolog
% Факт (базовый случай)
civ_has_unique_unit(Civ, Unit) :-
    civ_unit(Civ, Unit).

% Правило с несколькими условиями (И)
advanced_unit_check(Unit, Era, Resource) :-
    unit_available(Unit, Era),
    unit_resource(Unit, Resource).
```

Правило с **ИЛИ** внутри тела:

```prolog
melee_or_cavalry(Unit) :-
    unit_type(Unit),
    ( unit_resource(Unit, iron)
    ; unit_resource(Unit, horses)
    ).
```

Запрос к правилу ничем не отличается от запроса к факту:

```
?- advanced_unit_check(Unit, medieval, Resource).
% Unit = horseman,   Resource = horses
% Unit = swordsman,  Resource = iron
% ...
```

## 3. Логические операторы

| Оператор | Значение | Пример |
|----------|----------|--------|
| `,`      | И (and)  | `unit_type(U), era(ancient)` |
| `;`      | ИЛИ (or) | `unit_resource(U, iron) ; unit_resource(U, horses)` |
| `\+`     | НЕ (not) | `\+ U = settler` |

### 3.1. И (конъюнкция) — `,`

Все цели должны быть истинны. Порядок слева направо.

```
?- is_military_unit(U), unit_era(U, classical).
% юниты, которые военные И доступны в классическую эпоху
```

### 3.2. ИЛИ (дизъюнкция) — `;`

Срабатывает, если истинна хотя бы одна цель.

```
?- unit_resource(U, iron) ; unit_resource(U, horses).
% swordsman ; knight ; crossbowman ; horseman ; knight
```

### 3.3. НЕ (отрицание) — `\+`

`\+ Goal` истинно, если `Goal` **не доказуемо** (отрицание как отказ).

```
?- unit_type(U), \+ U = settler, \+ U = builder.
% все юниты, кроме гражданских
```

> Важно: `\+` не существует без переменных слева. Корректно
> `\+ U = settler`, а не `\+ U \= settler`.

### Приоритет

Высший — `\+`, затем `,`, самый низкий — `;`. Поэтому скобки менять
приоритет: `(A ; B) , C`.

## 4. Унификация

**Унификация** — процесс сопоставления двух термов с целью сделать их
идентичными, подставляя значения вместо переменных.

Результат:
- `true` — термы совпадают;
- подстановка переменных — свободные переменные получают значения;
- `false` — термы невозможно сопоставить.

### Правила унификации

1. **Константа с константой** — равны только если идентичны:
   ```
   ?- warrior = warrior.
   % true.
   ?- warrior = archer.
   % false.
   ```

2. **Переменная с константой** — переменная связывается (bind):
   ```
   ?- X = knight.
   % X = knight.
   ```

3. **Переменная с термом** — переменная связывается с термом:
   ```
   ?- X = unit(swordsman, iron).
   % X = unit(swordsman, iron).
   ```

4. **Переменная с переменной** — они становятся связанными друг с другом:
   ```
   ?- X = Y.
   % X = Y.
   ```

5. **Структуры** — унифицируются рекурсивно (голова с головой, аргументы с
   аргументами):
   ```
   ?- civilization(Civ, UA) = civilization(rome, UA).
   % Civ = rome.
   ```

### Пример из базы знаний

```
?- unit_resource(Knight, R) = unit_resource(knight, horses).
% Knight = knight, R = horses.
```

### Унификация — основа сопоставления в запросах

Когда Prolog пытается выполнить `unit_era(Unit, medieval)`, он унифицирует
этот терм с каждым фактом `unit_era(_,_)` и связывает `Unit` с фактическим
аргументом:

```
?- unit_era(Unit, medieval).
% унификация с unit_era(crossbowman, medieval) -> Unit = crossbowman
% унификация с unit_era(knight, medieval)       -> Unit = knight
% унификация с unit_era(trebuchet, medieval)    -> Unit = trebuchet
```

## 5. Бэктрекинг

**Бэктрекинг (возврат)** — механизм поиска решений с возвратом: если цель
не может быть доказана при текущих подстановках, Prolog откатывается назад
и пробует следующую альтернативу.

### Как это работает

1. Prolog ищет первое подходящее **предложение** (факт/правило), унифицируя
   голову запроса.
2. Если тело правила не доказуемо — происходит **откат**: восстанавливаются
   предыдущие подстановки переменных и пробуется **следующая** альтернатива
   (другое предложение, на шаг назад).
3. Так продолжается, пока не будет найдено решение или не кончатся варианты
   (тогда ответ `false`).

### Символ `;` в ответе

При запросе:

```
?- is_military_unit(U).
% U = warrior ;
% U = archer ;        <- пользователь нажал `;` — бэктрекинг
% U = horseman ;
% ...
```

По умолчанию показывается **первое** решение. Нажатие `;` (или пробел)
заставляет Prolog вернуться назад и искать следующее.

### Пример отката внутри правила

```prolog
same_resource_units(U1, U2) :-
    unit_resource(U1, R),
    unit_resource(U2, R),
    U1 \= U2.
```

Запрос `same_resource_units(knight, U2)`:
1. `unit_resource(knight, R)` → первое решение `R = horses`.
2. `unit_resource(U2, horses)` → `U2 = horseman`.
3. `knight \= horseman` → true. Ответ: `U2 = horseman`.
4. Нажимаем `;` → откат к шагу 2: `unit_resource(U2, horses)` →
   `U2 = knight`, но `knight \= knight` ложно → откат ещё раз:
   фактов с `horses` больше нет → возврат к шагу 1: `R = iron` → и т.д.

### Принудительный поиск всех решений

`fail` и `findall/3` заставляют Prolog пройти все варианты:

```
?- findall(U, unit_era(U, medieval), L).
% L = [crossbowman, knight, trebuchet].
```

### Символ `!` (cut)

**Cut** `!` отсекает альтернативы — запрещает бэктрекинг через точку разрыва:

```prolog
max_resource_unit(Unit, Resource) :-
    unit_resource(Unit, Resource), !.   % берём первое решение и останавливаемся
```

## Шпаргалка по запуску

```bash
# SWI-Prolog: загрузить базу и работать в REPL
swipl ai.pl

# Однострочный запрос из командной строки
swipl -f ai.pl -g "unit_available(Unit, medieval)" -t halt

# Docker
docker run --rm -v "$PWD:/app" swipl:latest swipl -f /app/ai.pl -g "civilization(rome, X)" -t halt
```

## Операторы и конструкции — сводная таблица

| Конструкция | Синтаксис | Назначение |
|-------------|-----------|------------|
| Факт        | `pred(arg).` | всегда истинное утверждение |
| Атом        | `ancient` | константа |
| Переменная  | `Unit`, `_` | заглавная буква; `_` — анонимная |
| Правило     | `H :- B1, B2.` | H если B1 и B2 |
| И           | `,` | конъюнкция |
| ИЛИ         | `;` | дизъюнкция |
| НЕ          | `\+ G` | отрицание (отказ от доказательства) |
| Унификация  | `=` | сопоставление термов |
| Неравенство | `\=` | отсутствие унификации |
| Cut         | `!` | отсечение бэктрекинга |
| Список      | `[H \| T]` | голова и хвост |
| Найти все   | `findall(X, Goal, L)` | сбор всех решений |
